# Little Office launch brief

This launch story and every person, customer count, competitor, and financial assumption in it are fictional. Little Office itself is a real local 2D application. No message is sent to an investor, reporter, or Slack workspace.

Little Office gives a small team a shared office for agent work. People assign work, follow progress, review deliverables, and keep the source conversation attached to the result. The launch audience is independent consultants and small studios handling several client requests each week.

The product worker must make a small real launch improvement in the supplied application's source. Add a welcome banner in `src/App.tsx` using class `launch-welcome`, with the sentence "Your office is open." and a "Send first request" button using class `launch-welcome__action` that opens the existing message composer. Use existing styles and avoid unrelated changes. Build it and describe the change. The local verifier will then stage and capture a disclosed responsive CSS regression for the later bug scene.

The marketing worker should write a launch plan with the audience, concrete use cases, channels, first-week activities, and several short slogans. Use only claims supported by this brief. Explain how source messages, parallel workers, review, and downloadable artifacts help someone finish their work. Do not claim real customers, investment, autonomous external messaging, or measured commercial results.

The forecast worker should calculate a six-month baseline from `assumptions.csv` and `customers.csv` using `forecast-contract.md`. Write a readable report plus a machine-readable `forecast.csv`. Describe all figures as fictional planning assumptions and distinguish revenue from operating contribution. Do not invent competitor news before it arrives.
